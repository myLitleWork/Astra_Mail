## Привязка пароля

Контекст включает идентификатор и путь профиля, аккаунт, логины, хосты,
порты и режимы IMAP/SMTP, адрес отправителя. Хосты нормализуются по регистру
ASCII и завершающей точке. Логины и адреса сохраняют точное значение.
Длины полей включены в сериализацию, поэтому разделители внутри значения
не позволяют получить контекст другого аккаунта.

Для каждого контекста создаётся отдельный файл в `~/.astramail/accounts`.
Имя — digest контекста через `crypto_generichash`, без пароля/открытых
реквизитов аккаунта в имени. **Сам контекст также помещён внутрь
аутентифицированного ciphertext**, перед паролем. Поэтому копирование
правильно зашифрованного файла A под именем B не открывает пароль A для B,
даже при одинаковом PIN. Это проверено настоящей libsodium.

Новый формат v2 хранит алгоритм KDF, salt, nonce, параметры и ограниченный
размер ciphertext. Перед KDF и выделением памяти проверяются заголовок,
полнота файла, длины и допустимые пределы параметров. Пустой/повреждённый
файл и неверный PIN возвращают отказ, очищая выходной пароль.

Текущий пароль в ThunderbirdSettings имеет собственную привязку к контексту.
Применение/загрузка другого профиля или аккаунта очищает его. Без правильного
PIN новый аккаунт остаётся заблокированным; автоматический выбор чужого
секрета отсутствует. Повторная установка PIN/пароля меняет только выбранную
запись. Временные буферы PIN/пароля и ключа очищаются при выходе из своих
областей; это не утверждение об очистке всех возможных копий в ОС.

## Переключение и устаревшие команды

Почтовая операция удерживает общий контекст до завершения. Изменение
аккаунта использует неблокирующую проверку: если операция идёт, изменение
отклоняется с сообщением, а старый контекст остаётся целым. Защищены также
низкоуровневые изменяющие методы ThunderbirdSettings, а не только меню.
Вложенные вызовы проверки/отправки/APPEND/экспорта используют тот же gate.

После выбора аккаунта вызывается PIN-меню. Для повторного входа добавлен
пункт «Разблокировать текущий почтовый аккаунт» в «Системе». Если для
аккаунта ещё нет ни записи, ни доступного старого секрета, меню предлагает
создать запись, а не вводить PIN к несуществующему файлу (AM-10).

Команды экспорта больше не хранят копию пароля на всё время жизни меню.
Сохранённые команды отправки/экспорта проверяют свой контекст перед
выполнением: команда, созданная для A, не может использовать пароль B после
переключения. Проверены реальный выбор аккаунта при занятом контексте и
попытка переключения при настоящем SMTP DATA.

Эта синхронизация необходима для AM-02. Она **не закрывает весь AM-08**:
гонка `lastActivity_` и общая обработка исключений фонового потока ещё
требуют отдельной проверки/исправления.

## Перенос старого secret.bin

Старый файл автоматически не загружается в выбранный аккаунт. При отсутствии
записи этого аккаунта пользователь вводит старый PIN, видит профиль,
аккаунт и оба сервера/логина и явно подтверждает привязку через `yes`.
Правильность выбранного аккаунта нельзя вывести из v1-файла: в нём такого
поля не было. Отказ или неверный PIN не создаёт новую привязку.

После успешного расшифрования сначала устойчиво фиксируется, к какому
контексту относится старый файл, затем создаётся новая зашифрованная запись.
Общая межпроцессная блокировка исключает одновременную привязку к A и B.
Если запись нового секрета сорвалась, перенос можно продолжить только для
того же контекста. Старый `secret.bin` остаётся побайтово неизменным.

После появления связанной записи отказ её расшифрования никогда не запускает
fallback на старый файл. Если старый формат не удалось расшифровать, аккаунт
остаётся закрытым; можно заново задать почтовый пароль для этого аккаунта.
Миграция проверена со старым форматом, созданным libsodium 1.0.11. V1 не
содержит номера алгоритма; для него сохранён прежний выбор ALG_DEFAULT
установленной библиотеки. Перенос v1 между системами с разным DEFAULT не
заявляется как проверенный сценарий.

## Совместимость и ограничения

`FsCompat.h`, каталог `src/UtilsFS` и корневой CMakeLists не изменены.
Условные блоки `__has_include(<filesystem>)` и выбор между std/experimental
в backend секретов и IMAP-клиенте **сверены с HEAD и совпадают**. Новые
модули используют существующий `fs`, без перехода на другой filesystem API.

Реальные профили, БД, письма, ключи и значения настроек не читались.
Рабочее хранилище пользователя не переносилось: весь перенос проверен
только на созданных тестовых файлах. Сборка и новые бинарники относятся
к отдельному стенду; Release/пакет и установленная программа не заменены.

Полноценный IMAP APPEND и реальные почтовые сервисы не испытывались.
Физическая потеря питания и все типы файловых систем не испытывались;
отказ записи воспроизводился управляемым EIO на rename. Полного
криптографического аудита libsodium и формального доказательства формата
не выполнялось. Сохранность всех копий секретов в памяти/свопе ОС не
заявляется. Независимая проверка всех оставшихся пяти находок ещё нужна.

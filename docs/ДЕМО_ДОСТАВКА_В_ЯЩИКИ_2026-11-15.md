- Проект: 3.3.4 / HEAD a576ae305b608928120f3d0d1ff8e6ebdc5961fd, прежний

- Метод: подготовка синтетического стенда по SSH, SMTP→Maildir→IMAP,
  точная проверка вложений, проверка prefs и SHA-256 созданных USB-файлов.
- Статус: стенд подготовлен и проверен на уровне протоколов. Полный ручной

- Baseline: прочитаны оба указателя, отчёты обычного пользователя от 12.11

## Подготовка

Для Linux-пользователя astramail-test настроены шесть почтовых аккаунтов
demo1@example.invalid … demo6@example.invalid. У всех единый синтетический
пароль по запросу пользователя; значение в журнал не включается. Старые
receiver/receiver2 также принимаются для совместимости прежних примеров.
Новых Linux-пользователей/административных прав не добавляли.

В обоих ранее созданных синтетических профилях Thunderbird добавлено по пять
аккаунтов к прежнему основному. Сохранены исходные prefs.js в
prefs.js.before-delivery-20261115. Изменение выполнено после ответа пользователя
«закрыл»; оставшийся процесс UID 1001 завершён штатным SIGTERM.
Параметры новых аккаунтов используют отдельные имена amdemo*, исходные
Local Folders и прочие настройки сохранены. Пароли Thunderbird не извлекались,
сохранённое зашифрованное хранилище AstraMail не читалось/не изменялось.

На 127.0.0.2:2525 работает отдельный Python SMTP с AUTH LOGIN, принимающий
только подготовленные адреса. После DATA сохраняются прежние flat-captures
и атомарно создаётся Maildir-копия для каждого адресата. Ошибка записи не
возвращает успешный ответ SMTP. Получатели вне списка не принимаются.

На 127.0.0.2:143 работает Dovecot 2.2.27 из официальных Debian-пакетов
2.2.27-3+deb9u5, распакованных без dpkg-установки. Источник:
[официальный архив Debian](https://archive.debian.org/debian/pool/main/d/dovecot/).
Поддерживаются настоящие INBOX, стандартные FETCH/BODYSTRUCTURE и Sent APPEND.
Почта хранится в созданном каталоге ~/AstraMail-DeliveryDemo-20261115/boxes.
Данные старого стенда не удалялись. Старая unit обычного пользователя остановлена
и заменена двумя новыми; стенд sg продолжает работать.

## Изоляция запуска

Transient units: astramail-delivery-smtp и astramail-delivery-imap. Без enable
и постоянной установки служб; после reboot запуск потребуется подготовить снова.
SMTP исполняется от astramail-test. IMAP-мастер использует root только в
частном окружении; исполняемые файлы/конфигурация защищены root в
/run/astramail-delivery-demo-20261115, процессы ящиков используют UID 1001/GID 1002.

Из-за встроенных путей Dovecot используется отдельный mount namespace:
overlay /usr/lib и bind комплектных модулей видны только процессам стенда.
Исполнение root-owned runtime разрешено только внутри этого namespace.
Основной /run сохранил noexec, в основной системе /usr/lib/dovecot не появился.
Конфигурация виртуальных пользователей опирается на штатные passwd-file/static
механизмы: [документация Dovecot](https://doc.dovecot.org/2.3/configuration_manual/authentication/passwd_file/).

Вариант постоянного /opt и системной ссылки был отклонён автоматической
проверкой до исполнения. Подтверждено отсутствие обоих отклонённых путей;
применён менее широкий временный вариант без этих глобальных изменений.
Промежуточные неуспешные попытки частного запуска устранены; успех заявлен
только после реальных auth/FETCH-проверок.

## MY_FLASH

Пользователь подтвердил подключение флешки; носитель выбран по метке и UUID
067AF3F97AF3E2FB. Созданы только отсутствовавшие папки:

- demo2@example.invalid … demo6@example.invalid — по два вложения (TXT и CSV).
- Одна папка с пятью этими адресами через запятую — одно общее TXT-вложение.
- AstraMail-Demo-20261115: ПОКАЗ.txt и samples с резервными копиями примеров.

Всего 6 исходящих писем, 11 исходных вложений, 10 ожидаемых доставок:
каждый из demo2…demo6 получает отдельное и групповое письмо, три вложения.
Все 11 файлов проверены по SHA-256 после записи, выполнен sync.
Релиз на флешку заново не копировался и не менялся; чужие файлы не читались.

## Проверки и ограничения

- Все шесть аккаунтов успешно прошли SMTP/IMAP с новым тестовым паролем.
- Пять индивидуальных доставок: SMTP DATA, реальный UID SEARCH/FETCH и
  BODYSTRUCTURE, побайтное совпадение декодированного вложения.
- Групповая доставка: одинаковый MIME подтверждён в пяти ящиках.
- APPEND в Sent отправителя успешен.
- Собственные автоматические selfcheck-письма удалены из IMAP после проверки;
  доказательства сохранены в checks. Перед ручным показом все шесть INBOX пусты.
- Обе новые службы и прежняя служба sg active; sudo обычному пользователю
  по-прежнему запрещён.

Сценарии: out/delivery-demo-20261115/{prepare_delivery.py,finish_demo.py,
check_delivery.py,prepare_flash.py}. Итоговые настройки учитывают исправления
совместимости из журнала запуска; первоначальный prepare_delivery отдельно
не является готовой командой повторной установки всего стенда.

Thunderbird GUI после изменения не запускался агентом. Пользователь должен
открыть Thunderbird, выбрать demo1 отправителем в AstraMail, отправить папки
MY_FLASH, затем нажать «Получить» у demo2…demo6. Если AstraMail сохранил старый
почтовый пароль, его надо заменить через сброс PIN аккаунта; серверная смена
не перезаписывает хранилище автоматически. Инструкция на USB это описывает.

Это локальная демонстрация без TLS/интернет-доставки. Код/версия/пакет
AstraMail, глобальная установка Dovecot, Release/commit/push не менялись.
Рабочие письма и реальные секреты не использовались.

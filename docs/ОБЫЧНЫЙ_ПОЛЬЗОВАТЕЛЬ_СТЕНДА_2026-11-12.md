## Подготовка и результат

По прямому запросу создан `astramail-test`, UID 1001, GID 1002, отдельный
домашний каталог и shell `/bin/bash`. Единственная группа — собственная
`astramail-test`. Членства в sudo/astra-admin/adm и других дополнительных
группах не выдавались. Задан случайный пароль; он передан пользователю в
чате и не сохранялся в артефакты/этот отчёт. `passwd -S` показывает P.

| Проверка | Фактический результат |
|---|---|
| `id astramail-test` | UID 1001, GID 1002, только группа 1002 |
| `sudo -l -U astramail-test` администратором | not allowed to run sudo |
| `sudo -n true` от нового UID | отказ; NO_SUDO_CONFIRMED |
| Локальная копия комплекта | `$HOME/AstraMail-Test-20261111`, принадлежит новому пользователю |
| Два тестовых профиля | `$HOME/AstraMail-ManualTest-20261111/home/.thunderbird` |
| Установка/PIN | отсутствуют; оставлены для ручного первого прогона |
| Целостность локальной копии | 31/31 записи KIT-SHA256 успешны |
| Исполнение без sudo | пакетный Run-AstraMail.sh --version от нового UID вернул 3.3.1 |
| SMTP/IMAP | авторизация синтетического demo1 выполнена от нового UID, LIST успешен |

Чтобы не смешивать результаты с текущим прогоном sg, создан отдельный
loopback-стенд: SMTP `127.0.0.2:2525`, IMAP `127.0.0.2:143`, профили указывают
на эти адреса. Письма/копии Sent сохраняются внутри тестового каталога нового
пользователя; выдавать доступ к закрытому каталогу sg не потребовалось.

Transient unit `astramail-standard-user-test.service` запущена администратором
без enable и постоянных файлов /etc. После открытия портов процесс сбросил
права до UID 1001/GID 1002, CapEff=0. Старая unit
`astramail-manual-test.service` и новая одновременно active. Перезапуск
административной службы обычному пользователю не разрешён; его вспомогательная
команда start-test-servers.sh только проверяет состояние без sudo.

Файлы подготовки: `out/standard-user-20261112/{demo_server.py,prepare_profiles.py,
START-HERE.txt,start-test-servers.sh}`. Штатный установщик/ELF/пакет 3.3.1 не
менялись, новый выпуск/версия/commit/push не выполнялись. Подготовлены только
профили и локальный комплект; приложение не устанавливалось новому пользователю.

## Ограничения и следующий шаг

Пользователь завершает текущий прогон, затем входит в отдельный графический
сеанс astramail-test и запускает 01/02 из локальной папки комплекта без sudo.
Вход с паролем через Fly/RDP здесь не проверялся. Проверка `--version` не
заменяет ручную установку, выбор профиля и полноценный UI.

Текущий USB остаётся смонтирован в сеансе sg: его mountpoint/права не менялись
во время пользовательского теста. Подключение/монтирование USB и доступ к нему
из обычного графического сеанса — отдельная часть предстоящего ручного теста.
Если образцы уже отправлены, их нужно восстановить на USB из samples.
В инструкции отмечено: 04-restore-samples рассчитан на выполнение из папки
комплекта на флешке, а не из локальной копии.

Синтетический IMAP предоставляет пустой INBOX и сохраняет APPEND/Sent;
интернет-доставка/TLS/получение непрочитанных не тестируются. Сервер временный
и не переживает перезагрузку. Программа/filesystem-флаги не менялись, рабочие
профили/ключи/почта других пользователей не читались и не использовались.

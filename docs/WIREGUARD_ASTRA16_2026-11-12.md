## Исходное состояние и выбранный способ

SSH astra16: Astra Linux Smolensk 1.6 x86_64, ядро `4.15.3-1-generic`.
В apt-кэше только локальные ISO-репозитории, пакетов wireguard/wireguard-tools/
wireguard-dkms нет. Заголовки текущего ядра первоначально отсутствовали,
`/dev/net/tun` присутствовал. VM подключена Host-only, IPv4 default route нет.

С официального сервера Astra загружены два штатных пакета
`linux-headers-4.15.3-1` и `linux-headers-4.15.3-1-generic`, версия
`4.15.3-1.astra13`. SHA-256 сверены с исходным apt-кэшем до установки и после
передачи на ВМ:

- common: `06d54f1a60cd4b2912ffa2ac05f4229437648958bdf50d16ac7a30263929c6fe`;
- generic: `d3907a7676e66b5a2facb22621565c408d9eeb382c97813695bf6d039ebe3299`.

Пакеты успешно установлены через dpkg. Сборка официального
wireguard-linux-compat 1.0.20220627 остановилась на несовпадении API IPv6
конкретных заголовков Astra (`ipv6_stub.ipv6_dst_lookup_flow` отсутствует).
Собранный модуль не установлен и не загружен; исходники модуля не исправлялись.
Также kernel build сообщил об отсутствующем libelf-dev для stack validation.
Заголовки остаются установленными; ядро/его загрузка не менялись.

Использован официальный [wireguard-go](https://git.zx2c4.com/wireguard-go/about/),
работающий через TUN. Исходники получены из официального Git, commit
`b3bc704ef0ee21a36298601a9e1e5ff90377ac52`; встроенная upstream-версия
0.0.20250522, commit датирован 24.10.2026. Сборка Go 1.27.4,
GOOS=linux, GOARCH=amd64, GOAMD64=v1, CGO_ENABLED=0, trimpath.
Переносимый Go загружен с go.dev, SHA-256 проверен по официальному API:
`178ab98950ac69ab25069307dc6ade79f3816e414cce95b4da166a115cde1e7e`.
Go установлен только в игнорируемую рабочую папку, не глобально Windows/ВМ.

## Проверки

- `wg --version`, `wireguard-go --version`, `sudo wg-quick --help` успешны.
  `bash -n` установленного wg-quick успешен.
- В приватных mount/network namespace созданы две дополнительные сетевые
  namespace, veth и два WireGuard TUN-интерфейса с синтетическими ключами.
  Штатный wg-quick при отсутствии kernel-модуля успешно перешёл на wireguard-go.
- Тестовые peer подтвердили handshake с обеих сторон, RX/TX ненулевые.
  Ping через туннель: 3/3 в каждую сторону, всего 6/6, потерь нет.

  синтетических ключей/конфигов. Финальный `wg show interfaces` пуст,
  проверочные wireguard-go-процессы отсутствуют.
- SSH после проверки доступен; default route по-прежнему отсутствует.
  Рабочие интерфейсы, DNS и маршруты не настраивались.

## Ограничения и следующий этап

Установка WireGuard и локальный шифрованный обмен подтверждены. Доступ к
конкретному VPN-серверу, внешний UDP, DNS из конфига, full-tunnel и автозапуск
ещё не проверены. Resolvconf не установлен; необходимость DNS-helper будет
определена по присланному конфигу. Для внешнего endpoint понадобится обеспечить
ВМ сетевой доступ: сейчас Host-only и нет default gateway.

Используется userspace-реализация, производительность kernel-модуля не заявляется.
Реальные конфиги/ключи/переписка/БД не читались. AstraMail, его релиз, исходники,
filesystem-флаги и содержимое флешки этой задачей не менялись. Сборки и публикации
AstraMail, commit/push не было. В проекте добавлены только этот отчёт/учёт;
файлы установки находятся под out.

Источники: [официальные WireGuard tools](https://git.zx2c4.com/wireguard-tools/refs/),
[backport для старых ядер](https://git.zx2c4.com/wireguard-linux-compat/about/),
[официальный репозиторий Astra](https://dl.astralinux.ru/astra/stable/1.6_x86-64/repository/),
[требования Go к Linux](https://go.dev/wiki/MinimumRequirements).

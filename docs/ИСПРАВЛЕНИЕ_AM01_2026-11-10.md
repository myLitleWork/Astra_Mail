## Получившееся поведение

SMTP больше не сообщает успех только по факту TCP-подключения. Проверяются
приветствие, EHLO, аутентификация, отправитель, каждый адресат, разрешение
передачи DATA и окончательное подтверждение сервера. Парсер собирает полные
ответы из фрагментов, понимает многострочные ответы и коды без текста.
Передача обрабатывает короткие записи и EINTR; строки DATA нормализуются и
экранируются по правилам dot-stuffing. Поведение сверено с
[RFC 5321, разделы 4.2, 4.3 и 4.5.2](https://www.rfc-editor.org/rfc/rfc5321.html).

По каждому адресу различаются три состояния:

| Состояние | Значение | Следующая попытка |
|---|---|---|
| Принято сервером | Получен положительный итоговый ответ после DATA для этого envelope-адресата | Этот адрес не включается повторно |
| Ожидает отправки | Приём не состоялся: адресат отвергнут либо письмо явно отклонено | Повторяется только этот адрес |
| Результат неизвестен | Окончательный ответ потерян либо процесс завершился во время попытки | Автоматическая отправка этому адресу запрещена до решения пользователя |

Положительный итоговый ответ означает принятие ответственности SMTP-сервером,
а не подтверждение прочтения или конечной доставки в ящик.

Пример проверенного сценария: сервер принял A и отверг B. Для A передаётся
письмо, папка остаётся в исходящих с результатами A=принято, B=ожидает. После
перезапуска новый процесс передаёт только B. Папка удаляется только когда
подтверждён приём всеми адресатами. При потерянном ответе A остаётся
неподтверждённым; точно отклонённый B при этом можно повторять отдельно.

## Сохранение результата и действия пользователя

Скрытый файл `.astramail-delivery-state` рядом с вложениями содержит снимок
адресатов, результат по каждому, контекст сервера/отправителя и отпечаток
содержимого вложений. Состояние записывается через временный файл 0600,
fsync, rename и fsync каталога. **До сетевой передачи** адреса попытки получают
устойчивую отметку неизвестного результата. После ответа она заменяется на
подтверждённый итог. Если процесс погиб или итог не удалось записать,
сохранённая отметка предотвращает автоматический дубль.

Завершение процесса до фактической передачи тоже может оставить такую
консервативную отметку. Тогда потребуется проверить результат вручную.
Отпечаток FNV-1a используется для обнаружения случайного изменения вложений;
это не криптографическая аутентификация состояния.

В меню «Исходящие» добавлен пункт «Результаты отправки». Для неизвестного
результата можно выбрать адрес и либо подтвердить приём после проверки по
серверу/адресату, либо явно разрешить повтор с предупреждением о возможном
дубле. Для непринятого адреса можно исправить email следующей попытки.
Подтверждённые адресаты при этом не сбрасываются. Каждое изменение требует
явного подтверждения `yes` в приложении.

Параллельная отправка **одного** письма исключается отдельной блокировкой.
Новые вложения не подмешиваются импортом с флешки в папку с сохранёнными
результатами: они остаются на флешке с объяснением. Служебные файлы учёта
не включаются во вложения. Ошибки и частичный результат показываются
пользователю; общий результат группы больше не выдаётся за полный успех.

Отказ сохранения копии в IMAP Sent не сбрасывает уже подтверждённый SMTP-
результат. Сведения записываются до APPEND, поэтому перезапуск после сбоя
APPEND не повторит уже принятое письмо.

## Исправления

`scripts/install_astramail.sh:7` определяет корень пакета относительно себя,
на один уровень выше scripts. Текущая папка терминала не выбирает бинарник.
Контрольные суммы проверяются на исходном носителе без исполнения ELF.
Копируются только перечисленные в checksum файлы с проверкой путей;
случайные runtime-файлы рядом с portable-программой в установку не попадают.

Комплект переносится в `~/.local/opt/AstraMail`, включая библиотеку,
запускатель, CSV, лицензии и руководства. Команда `~/.local/bin/AstraMail`
запускает установленный Run-AstraMail.sh. Проверка версии исполняется только
после копирования на локальный диск (`install_astramail.sh:122`).

Обновление готовится в отдельном `.AstraMail.install.*`. Прежняя папка
программы и существующие команда/ярлыки сохраняются; при обработанной ошибке
замены выполняется восстановление (`install_astramail.sh:96`). Переносятся
шесть известных конфигурационных файлов программы рядом с прежним ELF,
включая переход со старой установки в `.local/bin` (`:128`). HOME-хранилища
почты/секретов не сканируются. «Готово» выводится только после проверки версии
через установленную команду (`:174`).

Добавлены запись меню и ярлык в настроенном каталоге рабочего стола.
Отключённый рабочий стол учитывается. Обнаружено, что штатная xdg-user-dir
Astra 1.6 использует незакавыченные пути и eval. Данные XDG_DESKTOP_DIR
разбираются без исполнения shell-кода; проверены пробелы, кириллица,
обратная косая черта, кавычки, доллар, обратная кавычка и процент.
Exec экранируется для desktop key file и его аргументов, запуск идёт через
`/bin/sh` (`install_astramail.sh:145`). `Terminal=true` сохранён.

Добавлено [руководство установки](../tutorials/Установка.md), ссылки README и
руководства запуска. CMake, FsCompat, выбор filesystem и флаги стандарта
этой задачей не менялись.

## Релизные gates

В `tests/test_installer.py` добавлена интеграционная проверка настоящего
пакета. `scripts/Test-AstraMailRelease.sh:11` монтирует источник read-only/noexec
в отдельном mount/network namespace и выполняет проверки от непривилегированного
UID. Настройки и пути тестов синтетические. GLib запускает `--version` через
native desktop parser; для этой автоматической пробы окно терминала подавлено,
а наличие `Terminal=true` в поставленном ярлыке проверяется отдельно.

`scripts/Test-AstraMailPackaged.py:17` получил режим установленной копии:
на новом HOME выполняется настоящий установщик, затем приложение через
установленную команду проходит полный PTY/UI-импорт CSV и чистый выход.
Проверяются три сохранённых синтетических контакта.

Оба обязательных этапа выполняются до создания artifacts.zip
(`scripts/AstraMailRelease.py:122`). Лог `installer-tests.log` возвращается
в локальный run. Manifest и Windows verifier требуют
`isolatedInstaller=true` и `installedUiCsvImport=true`. На builder preflight
проверяет GI/Gio; дополнительные зависимости не устанавливались.

Первый canonical запуск завершился ненулевым exit на preflight из-за передачи
кавычек новой GI-команды через PS 5.1/SSH. Версия ещё оставалась 3.3.1,
компиляция не начиналась. Кавычки исправлены; следующий запуск прошёл полностью
и поднял patch ровно один раз. Одновременных выпусков и retry после bump не было.

свободное место и отсутствие папки новой версии. Создан только новый каталог

- `KIT-SHA256` — суммы 24 файлов набора.

из скрипта UTF-8 без BOM. Скрипт оснастки сохранён с BOM; продолжение сверило
уже записанные файлы без замены и добавило инструкцию/KIT-SHA256.

## Ограничения

Новый ручной сеанс Fly/RDP, окно терминала из настоящего GUI-ярлыка и
пользовательская отправка с USB оставлены самостоятельной тренировке.
Текущая флешка во время записи находилась в Windows; noexec проверен
на настоящем ELF в отдельном mount namespace Astra, а не новым физическим
подключением этой USB к ВМ. Внешняя синхронизация Google Drive не проверялась.

Рабочие БД, переписка, ключи и значения настроек ради примеров не читались.
Автоматические UI/SMTP/IMAP использовали изолированные синтетические данные.
Произвольное отключение питания и SIGKILL во время обновления не моделировались;
проверенный откат относится к обработанной ошибке записи. Сохранённые резервные
копии не удалялись. Прежняя отдельная ошибка attachment_groups.conf не входит
в эту доработку и не объявляется исправленной переносом конфигурации.

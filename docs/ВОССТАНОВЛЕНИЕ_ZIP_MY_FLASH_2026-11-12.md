- Дата: 12.11.2026, Asia/Yekaterinburg (UTC+05).
- Запрос: снимок отказа `01-install-demo.sh` при проверке KIT-SHA256;
  продолжение разрешённой подготовки пакета для самостоятельной тренировки.
- Версия / HEAD: 3.3.2 / `a576ae305b608928120f3d0d1ff8e6ebdc5961fd`,
  прежний dirty выпуска/установщика/руководств/MenuCreator и отчётов сохранён.
- Baseline: прочитаны оба указателя, правило учёта и
  [отчёт выпуска и доставки](УСТАНОВЩИК_И_РЕЛИЗ_3.3.2_2026-11-12.md).
  На исходной записи в Windows KIT прошёл 24/24; та запись сохранена как
  исторический результат, а не как гарантия последующей неизменности USB.
- Метод и статус: SSH, проверка активного USB mount, SHA-256, сравнение ZIP
  metadata и 19 известных payload-файлов, восстановление одного архива,
  fsync/sync и контрольное чтение. **Завершено: KIT на физической флешке
  снова проходит 24/24.** Пользовательский установщик не исполнялся.
- Исправления: заменён только ZIP в новом комплекте на MY_FLASH. Исходники,
  версия, опубликованный пакет, установщик, KIT-SHA256 и sidecar не менялись.
  Новая сборка, публикация и commit/push не выполнялись.

## Проверенное состояние

На снимке checksum не совпадает только у AstraMail-3.3.2.zip. SSH подтвердил
то же состояние: 23 остальных файла совпали, включая распакованный пакет,
обе вспомогательные команды, инструкцию и SHA256-sidecar. Сам KIT-SHA256
совпадает с записью доставки:
`fb284a776b38ea2804c77c16197f848ee360218220b449e23804c61957aef97a`.

При диагностике присутствовали несколько старых mount-записей того же UUID.
Активная флешка определена через lsblk: MY_FLASH, removable, /dev/sde1,
mountpoint `/run/user/1000/media/by-uuid-067AF3F97AF3E2FB___`, noexec.
Работа велась только с `AstraMail-3.3.2/AstraMail-3.3.2.zip` на этом mount.
Монтирование и системные политики не менялись.

| Свойство | Канонический ZIP | ZIP на USB до восстановления |
|---|---|---|
| Размер | 3 418 267 байт | 3 419 681 байт |
| SHA-256 | `45c296f4f0c83e7424e3a232560795da33a5e7eba7f2537758703cf2e0543394` | `e5a8e2989ba84b37a360de0d6ace33fbc170cf852e0d4f8cc9f0d6d89bcd2d94` |
| Число entries | 19 | 19 |
| Содержимое файлов после сопоставления имён | Baseline | 19/19 побайтно совпали |
| Metadata | Исходные поля | Изменены flag_bits, create_system, external_attr, extra |
| extra каждого entry | 0 байт | 32 байта |
| Кириллические имена | Корректные имена канонического ZIP | Четыре имени сопоставились только после декодирования исходных байтов как CP866 |

Проверены именно 19 известных файлов релиза; рабочие настройки и почта не
читались. Первое сравнение Python zipfile остановилось на кириллическом имени,
поскольку без UTF-8-флага библиотека читала байты как CP437. После явного
однозначного сопоставления с CP866 все 19 содержимых совпали по SHA-256.

Следовательно, причина несовпадения SHA — изменённое представление ZIP:
служебные поля и кодировка имён. Это согласуется с пересохранением архива.
Программа или действие, которым архив изменён, **не установлены**. Оснований
объявлять повреждёнными бинарник или распакованный пакет нет: их суммы совпали.

## Восстановление и проверки

Источник — точная опубликованная копия
`/tmp/astramail-release.KBQhy06I/published-verify.zip`, оставшаяся от завершённого
canonical Release. Её SHA-256 перед записью совпала с release-result.json
и локальным `out/release-runs/20261112-161051-78570227/published-verify.zip`.
Новая проверка CloudRoot на этом этапе не выполнялась.

Изменённый ZIP предварительно сохранён под
`/tmp/astramail-usb-integrity.u5XcPsYY/modified-before-repair.zip` и скопирован
в `out/usb-integrity-20261112/modified-before-repair.zip`; его SHA-256 сверена.
Новая копия записана во временный файл в том же каталоге USB, проверена по
SHA-256, затем атомарно заменила целевой ZIP. Выполнены fsync/sync, сброс
кэша чтения этого файла через posix_fadvise и повторное чтение.

- Восстановленный ZIP: исходные 3 418 267 байт и SHA-256 `45c296f4…e0543394`.
- `sha256sum -c KIT-SHA256` непосредственно с физической USB: **24/24**, exit 0.
- Проверка опубликованного sidecar через sha256sum на нормализованном потоке:
  **ZIP цел**, exit 0. Сам файл sidecar сохранён побайтно.
- Пользовательские `01-install-demo.sh`/`02-run-demo.sh` и пакет не изменялись;
  следующая попытка установки остаётся пользователю.

## Находки и ограничения

| ID | Находка | Состояние |
|---|---|---|
| USB-ZIP-01 / P2 | На носителе изменены bytes ZIP, исходная checksum не совпадает и блокирует тренировочную установку | Исправлена заменой на канонический ZIP; проверена на USB, 24/24 KIT |
| USB-SHA-02 / P3 | Опубликованный Windows sidecar содержит CRLF; прямой `sha256sum -c AstraMail-3.3.2.zip.sha256` на этой версии Astra воспринимает CR как часть имени файла | Совместимость publisher с этой формой чтения остаётся открытой; проверено чтение нормализованного потока. Учебная команда использует LF-файл KIT-SHA256 и этим ограничением не затронута |

Во время первой дополнительной проверки sidecar получен отказ открытия имени
с конечным CR, уже после успешного восстановления ZIP и 24/24 KIT. Это отдельная
ошибка формата чтения. Повторная read-only проверка с нормализацией CRLF
подтвердила правильную сумму; повторной замены ZIP не было.

Полные Release/native/UI-проверки от предыдущего выпуска не повторялись:
исходники и распакованный пакет не менялись. GUI, установка в учебный HOME,
PIN и отправка оставлены пользователю. Изменения архиватором при последующих
действиях пользователя не моделировались; конкретный виновник изменения
не установлен. Реальные БД, переписка, ключи и значения настроек не читались.

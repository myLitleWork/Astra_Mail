## Установка и настройки

Astra Linux Smolensk 1.6 x86_64, ядро 4.15.3-1-generic.
Установлены два штатных пакета без обновления иных пакетов:

| Пакет | Версия | SHA-256 скачанного DEB |
|---|---|---|
| xrdp | 0.9.6-1astra1 | `e6c89917893feaf0457ad224d96127beefcace9b91ecfbd34285e3b5006adcfe` |
| xorgxrdp | 1:0.2.6-1astra1 | `6978218adad20e5ae72a4eb20eb0c453971cf70ebe64780ec8fa02675492d8b2` |

Источник — официальный репозиторий Astra 1.6; суммы сверены с apt-кэшем
ВМ до передачи и повторно на госте до dpkg -i. Новый desktop не ставился:
системный x-session-manager уже указывает на fly-wm, штатный startwm.sh
вызывает /etc/X11/Xsession. Он не изменялся. Для входа используется Xorg.

Службы xrdp и xrdp-sesman запущены и включены в автозапуск.
RDP слушает TCP/3389 на интерфейсах ВМ; sesman TCP/3350 только на 127.0.0.1.
Настройки/port forwarding Windows и VMware не менялись.

Стандартный TLS key.pem был недоступен пользователю xrdp. Создан отдельный
самоподписанный серверный сертификат RSA-2048/SHA-256 с CN=astra16:
`/etc/xrdp/rdp-server.crt`, приватный ключ `/etc/xrdp/rdp-server.key`.
Приватный ключ root:xrdp 0640, доступ xrdp проверен через test -r без чтения
ключа в вывод. Исходные xrdp.ini/sesman.ini сохранены в закрытом каталоге
`/var/backups/xrdp-setup-20261112/`.

Установлены security_layer=tls, ssl_protocols=TLSv1.2 и пути выделенного
сертификата/ключа. AllowRootLogin=false; обычная аутентификация пользователя
Astra сохранена. Пароли не читались и не менялись, новые пользователи не создавались.

Публичный fingerprint сертификата SHA-256:
`9CA56B741714F9CB91AABE00DFC7C076A7F0F8E3BE41FE1650AE4A6AFF97D248`.

## Проверки

- systemctl is-enabled xrdp/xrdp-sesman: enabled/enabled;
  is-active: active/active. WireGuard wg-quick@wg0 также active.
- ss -ltnp: listener 3389, sesman 3350 на loopback.
- Из Windows выполнены TCP connect, стандартный X.224 RDP Negotiation Request
  с PROTOCOL_SSL, подтверждён выбор TLS сервером, затем SslStream handshake
  TLS 1.2. Сертификат принят только при точном совпадении SHA-256 с полученным
  по доверенному SSH. Отключения проверки сертификатов не применялось.
- TCP/3389 VPN-адреса ВМ тоже доступен с Windows.
- В начале задачи текущий DHCP-адрес изменился. Новый адрес найден строго
  по известному MAC в leases VMware, SSH host key проверен по прежней привязке.
  Обновлён только HostName astra16 в SSH config с резервной копией;
  прежняя проверка host key и остальные блоки сохранены.

Вход в Xorg/Fly с паролем пользователя и работа полного удалённого рабочего
стола не проверялись; порт/TLS не выдаются за такую проверку. Фактический
автозапуск после перезагрузки не выполнялся, ВМ не перезагружалась.

Для пользователя: mstsc, локальный адрес текущей ВМ либо её VPN-адрес,
TCP/3389; сеанс Xorg, логин sg и его существующий пароль Astra.
Текущий локальный адрес выдан DHCP и может измениться. Значения адресов
и персональные пути в этот отчёт не включены; сообщены пользователю отдельно.

Пакеты установки сохранены в `out/rdp-astra16-20261112/`.
Код/пакет AstraMail, filesystem-флаги и флешка не менялись;
сборки/публикации/commit/push не было. Реальные письма/БД и пользовательские
профили не читались, приватные ключи и пароли в журналы не включены.

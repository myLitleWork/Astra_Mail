## Содержимое и находки

Прочитаны все 28 строк `scripts/install_astramail.sh`. Скрипт копирует
один файл в `$HOME/.local/bin`, выдаёт ему право исполнения и записывает
терминальный desktop-ярлык. Загрузок, sudo, удаления почты или чтения
настроек в нём нет. Существующие бинарник и одноимённый ярлык
перезаписываются; проверки успешности и сохранения прежней версии нет.

| ID / важность | Проблема и последствия | Доказательство | Статус |
|---|---|---|---|
| INSTALL-01 / P2 | `BIN="AstraMail"` ищется относительно текущей папки терминала. Из scripts файл не найден; из другой папки устанавливается чужой одноимённый файл. Простая замена на `../AstraMail` сохранит зависимость от текущей папки | install_astramail.sh:4,6,12; AstraMailRelease.py:75,79–83; синтетические случаи scripts/unrelated | Открыта, воспроизведена в Git Bash |

`Terminal=true` соответствует консольной программе. Кавычки в shell-командах
с HOME/DEST уже есть, но они не экранируют содержимое строки Exec внутри
созданного desktop-файла. Подставляемая переменная раскрывается при создании
ярлыка, а не при последующем запуске.

Release сейчас проверяет установщик только через `bash -n`
(`scripts/AstraMailRelease.py:80–83`). Проверка присутствия и SHA-256
в `scripts/Test-AstraMailPackage.ps1:15,29–30` подтверждает поставку нужных
байтов, но не правильное поведение установки.

## Предложения

1. Определять корень пакета относительно самого скрипта. Для текущего
   размещения `scripts/install_astramail.sh` он на один уровень выше:

   ```bash
   script_dir=$(CDPATH= cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
   package_dir=$(CDPATH= cd -- "$script_dir/.." && pwd)
   src="$package_dir/AstraMail"
   ```

   Проверять и копировать именно `$src`, независимо от текущей папки.
   Это предлагаемый фрагмент; в исходники он не внесён.

2. Останавливать установку при ошибках; проверять обязательные файлы до
   замены прежней программы и выводить успех только после успешных шагов.
   Для обновления сначала подготовить новую локальную копию, сохранив старую
   до успешной проверки. `set -euo pipefail` полезен вместе с явными
   проверками и понятной диагностикой.

3. Рекомендуемый вариант — сохранять комплект программы в отдельном
   пользовательском каталоге, например `~/.local/opt/AstraMail`, включая
   `AstraMail`, `lib`, `Run-AstraMail.sh`, лицензии, справочные материалы и CSV.
   Команду в `~/.local/bin` и desktop-ярлык направить через запускатель,
   который подключает библиотеку установленной копии. Сохранить привычное
   имя команды `AstraMail`. Минимальный вариант с одним ELF допустим лишь
   при явной проверке системной libsodium и описанном требовании к ней.
   Текущий пакет уже содержит библиотеку, поэтому полный перенос практичнее.

4. Определять каталог рабочего стола через доступный `xdg-user-dir DESKTOP`,
   проверить результат на Astra/Fly и обработать отсутствие утилиты/каталога.
   Добавить запись меню в `~/.local/share/applications`; корректно экранировать
   Exec, сохранить `Terminal=true`. Проверить фактический запуск ярлыка.

5. Учитывать noexec USB: читать и проверять суммы исходных файлов на USB,
   копировать на локальный диск и только затем исполнять проверку версии.
   `Verify-Package.sh` запускает ELF через Run-AstraMail.sh, поэтому его запуск
   непосредственно с noexec-носителя повторит уже известную ошибку стенда.

6. После исправления отдельно проверить установку с разными текущими
   каталогами, путями с пробелами/кириллицей, без Desktop, с отказом записи,
   обновление существующей копии, запуск через ярлык и комплектную libsodium.
   Изменённый установщик включить в следующий canonical Release; замена
   одного файла в уже опубликованном ZIP нарушит прежние контрольные суммы.

## Выполненные проверки и ограничения

Материалы: `out/installer-review-20261112/review.sh` и
`out/installer-review-20261112/fixture.952kC0aN/*.log`.
Вызов: Git Bash `--noprofile --norc ./out/installer-review-20261112/review.sh`.
В качестве бинарников использованы обычные текстовые маркеры; они
не исполнялись. Все HOME и результаты находятся в этой fixture.

| Сценарий | Результат неизменённого установщика |
|---|---|
| Из корня пакета, Desktop существует | exit 0, установлен пакетный маркер и создан ярлык |
| Из scripts | exit 1, бинарник не найден |
| Из посторонней папки с одноимённым файлом | exit 0, установлен посторонний маркер |
| Без Desktop | ошибки cat/chmod, ярлыка нет, но «Готово» и exit 0 |
| `.local/bin` заблокирован обычным файлом | ошибки mkdir/cp/chmod, бинарник не установлен, но «Готово» и exit 0 |

Все 5 проверок ожидаемых наблюдений прошли; это воспроизведение поведения,
включая дефекты, а не пять успешных установок. Дополнительно `bash -n`
прошёл, SHA-256 четырёх входов совпали с baseline, 16/16 payload — с manifest.

Новые Astra runtime, UI/desktop, ELF/dependency loader, обновление рабочей
установки, сборка, публикация и SSH-изменения не выполнялись. Рабочие БД,
переписка, ключи и значения пользовательских настроек не читались.
Прежний Release 3.3.1 и стенды остаются в прежнем состоянии. Все находки
открыты; исправление установщика данным запросом не выполнялось.

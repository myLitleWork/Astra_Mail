## Причина и исправления

В main отсутствовали вызовы трёх уже реализованных bootstrap-функций.
Поэтому наличие defaults и успешный ручной сброс не обеспечивали создание
subject_rules.conf, attachment_groups.conf и outgoing_subject_rules.conf
при первом запуске. В `main.cpp:67` добавлены все три вызова с **false**,
до выбора профиля и запуска фоновой работы.

Общий `ensureFile` молча пропускал отказ открытия/записи. Теперь
`src/Configs/Confg/ConfigBootstrap.cpp:19`:

- сохраняет непустые обычные файлы при force=false, не открывая их на запись;
- заполняет отсутствующие и пустые файлы соответствующими ConfigDefaults;
- проверяет ошибки определения типа/размера, отклоняет каталог вместо файла;
- создаёт родительские каталоги и проверяет результат;
- проверяет реальное открытие для записи и итог записи/закрытия потока;
- при ошибке бросает runtime_error с путём, операцией и доступной системной
  причиной; сообщение не содержит содержимого конфигурации.

Доступность записи проверяется самой операцией, без отдельной проверки
permission bits, способной дать неверный результат для ACL/реального доступа.
Существующему непустому файлу при обычном старте право записи не требуется.

`main.cpp:75` выводит понятное сообщение и возвращает 1 при отказе подготовки.
`src/menu/Commands/Configs/CmdResetConfig.cpp:36` сохраняет force=true,
подтверждение, отмену и паузу результата. При исключении показывает ошибку
вместо ложного [OK] и возвращается к вызывающему меню.
Контракт исключений описан в ConfigBootstrap.h.

| ID | Находка | Статус на 16.11.2026 |
|---|---|---|
| CONFIG-BOOT-01 | Три файла правил не создавались при обычном запуске | Исправлена в исходниках и проверена в выполнении |
| CONFIG-IO-01 | Ошибки создания каталогов, открытия и завершения записи bootstrap игнорировались | Исправлена в исходниках и проверена в выполнении |
| RESET-IO-01 | Сброс сообщал об успехе после неудачной записи | Исправлена в исходниках и проверена в выполнении |

Ни одно из этих исправлений пока не вошло в новый проверенный пакет.
Прежняя EXPORT-CONFIG-01 описывает отказ конкретной установленной копии;
её файлы и права в этой задаче не обследовались. Новый тест подтверждает
устранение дефекта первоначальной инициализации в исходниках.

## Автоматические тесты и результаты

Добавлены `tests/config_bootstrap_driver.cpp` и
`tests/test_config_bootstrap_native.py`. Драйвер использует настоящие
ConfigBootstrap, ConfigDefaults, ConfigPaths и CmdResetConfig из Debug-библиотек.
Основные проверки запускают полный исполняемый файл с закрытым stdin,
копией бинарника, отдельными HOME и CWD. Значения defaults берутся из
production-функций и сравниваются побайтно.

Новый набор подключён к полному native-прогону в
`scripts/Test-AstraMailRelease.sh:23` и `tests/run_am11_isolated.sh:12`.
Режим запуска только am11 сохранён. Подключение тестов не запускает выпуск.

**16/16 тестов успешны**, в том числе отдельные подслучаи для всех семи
bootstrap-файлов:

- первый запуск без файлов и родительских каталогов;
- два повторных запуска: сохранены пользовательские байты и mtime;
- восстановление каждого отсутствующего файла без изменения остальных;
- заполнение пустых файлов;
- подтверждённый ручной сброс: меняется только выбранный файл на defaults;
- отказ/EOF/незавершённое подтверждение: все файлы сохраняются;
- существующие непустые файлы без права записи сохраняются;
- отсутствующий файл в каталоге без права записи;
- невозможность создать каталоги HOME, файл вместо компонента пути;
- каталог вместо конфигурации, ошибка stat при закрытом доступе к родителю;
- пустой файл без права записи;
- реальный отказ завершения записи через RLIMIT_FSIZE=1 с SIGXFSZ=IGN;
- неудачный ручной сброс: путь и ошибка видимы, [OK] отсутствует,
  исходные байты сохранены, пауза результата сохранена;
- --version не создаёт конфигураций.

## Ограничения и поставка

исполнение всех их обработчиков.

не запускались и не обновлялись. Версия и app-version.json сохранены.

CMake, FsCompat, выбор filesystem и флаги стандарта не менялись.
Для будущих изменений bootstrap/main/сброса повторить новый набор и native;
перед поставкой отдельно выполнить штатный разрешённый release workflow.

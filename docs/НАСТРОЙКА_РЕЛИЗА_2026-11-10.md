## Изменения и контракт

Канонический вход — [tools/release.bat](../tools/release.bat), вызывающий
[Build-AstraMailPackage.ps1](../scripts/Build-AstraMailPackage.ps1) под Windows
PowerShell 5.1. Общие TOOLS находятся через неизменённую копию
`Find-WorkspaceReleaseRoot.ps1` из шаблона; фиксированной глубины каталогов нет.

Перед mutation выполняются preflight SSH/toolchain/UTF-8/изоляции и настроенной
папки публикации, затем общий project mutex. Fingerprint ограниченных
release-входов условно повышает patch до сборки; первый выпуск — 3.3.0.
Одинаковые входы повторно номер не расходуют. Retry после уже выполненного
sync использует `-SkipVersionBump`. Debug/CMake сами версию не повышают.

Исходники по allowlist с SHA-256 передаются в новый приватный каталог builder.
`CMake 3.7.2 / GCC 6.3 / Python 3.5.3 / libsodium 1.0.11` собирают Release.
Версия `app-version.json` встроена в ELF и меню; `--version` возвращает её до
чтения профиля и создания пользовательских настроек. Имя `AstraMail` сохранено.

После native gates формируется чистый пакет: бинарник, libsodium.so.18,
лицензионные уведомления libsodium/GCC runtime, launcher/verifier, README,
metadata, два русских руководства и CSV. ZIP-перенос через .NET/Python
сохраняет русские имена. На Windows проверяются payload, manifest, checksums,
версия, ELF64 и отсутствие лишних файлов, включая скрытые.

Публикация использует штатный `Publish-ReleasePackageIfConfigured.ps1` и
атомарную пару ZIP+SHA256 с прежним приоритетом CloudRoot. После неё именно
опубликованный ZIP передаётся обратно на astra16: распаковка, SHA-256 всех
файлов, `--version` и CSV-импорт обязаны пройти до exit 0. Сценарий сохраняет
структурированный `release-result.json` с фактическими путями и
`ArchiveVerifiedOnTarget=true`. Отдельные run и прошлые сборки сохранены.

Root CMake получил только `include(cmake/AstraMailVersion.cmake)`. Флаги
gnu++17/14, stdc++fs/static-libstdc++, UtilsFS/FsCompat и оба блока выбора
`__has_include(<filesystem>)` сохранены. Обычный POST_BUILD экспорт и install
target прежние; canonical build использует отдельный HOME.

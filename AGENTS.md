# Учёт аудитов проекта Astra_Mail

Область — этот проект. Дополнение касается учёта проверок.

- Перед аудитом читать `docs/АУДИТЫ.md`, последний отчёт нужной темы и указатель
  `TOOLS/workspace/АУДИТЫ.md`. Сверять изменения после записанного baseline.
- После проверки сохранять отчёт в docs, обновлять оба указателя по
  `TOOLS/instructions/УЧЁТ_АУДИТОВ.md`: дата, версия/HEAD/dirty, область, метод,
  находки, исправления, выполненные проверки и ограничения обязательны.
- Статическая сверка, runtime и пакет — разные факты. Отсутствие записи не
  считать доказательством отсутствия аудита. Отчёты в tutorials не помещать.
- Реальные базы, переписку, ключи и значения настроек не читать ради примеров.
- Явный read-only запрещает запись даже журнала: подготовить запись в ответе
  с отметкой, что на диск она не сохранена.

## Release

- Канонический вход — `tools/release.bat` или `scripts/Build-AstraMailPackage.ps1`.
  Полный порядок и ограничения: `docs/СБОРКА_И_РЕЛИЗ.md`.
- Цель: Astra Linux 1.6 x86_64, по умолчанию SSH `astra16`. Общие TOOLS
  искать только через `scripts/Find-WorkspaceReleaseRoot.ps1` из шаблона.
- `app-version.json` — канон версии. До компиляции fingerprint release-входов
  условно повышает patch; повтор после неудачи — `-SkipVersionBump`.
- До возврата 0 завершить Release, обязательные native/PTY/CSV gates, verify
  package и штатную публикацию ZIP+SHA256 при настроенном CloudRoot.
  Ждать ту же session; не запускать второй выпуск во время первого.
- Рабочие настройки/почта/секреты в пакет не входят. Образец CSV обязателен
  и проверяется настоящим импортёром и полным UI на синтетическом HOME.
- Простая CMake/Debug-сборка не публикует пакет и не меняет номер версии.
  Filesystem-выбор, FsCompat и флаги стандарта сохранять.
